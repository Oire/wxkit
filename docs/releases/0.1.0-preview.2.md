The second preview of WxKit adds Linux and macOS, so it now runs on Windows, Linux, and macOS, each on x64 and ARM64. Install it with `dotnet add package WxKit --prerelease`.

## What is new

- Linux, through wxGTK, on `linux-x64` and `linux-arm64`. An application needs GTK 3, which desktop Linux has, but not its development files, and a Native AOT publish needs `clang` and zlib's development files, as on any Linux. The packages work on Ubuntu 22.04 and anything newer.
- macOS, through wxOSX, on `osx-arm64` and `osx-x64`, from macOS 12. Call `Application.Run` from `Main`, since Cocoa only runs a user interface on the main thread.
- App bundles. Publishing for macOS makes one, such as `Hello.app`, named after `ApplicationTitle` and identified by `ApplicationId`, as in .NET MAUI. It is signed ad hoc, or with a Developer ID in `WxKitCodesignIdentity`, with the hardened runtime and the entitlements .NET needs, so it can be notarized. The repository's [building and packaging](https://github.com/trypsynth/wxkit/blob/master/docs/design/building-and-packaging.md#macos-app-bundles) docs describe it.
- `VerticalScrollBar` is negative, as wxWidgets's `wxVSCROLL` is, which matters on 64-bit Linux and macOS. The generator now takes the real headers' `#define` values where it can work them out.

## Platform differences

- `Accessible` describes a self-drawn control through Microsoft Active Accessibility, so on Linux and macOS it does nothing yet, and their own accessibility, through ATK and NSAccessibility, describes the standard controls.
- A few members only do something on some platforms, such as `RegisterHotKey` on Windows and macOS, a text control's spell checking, `EnableProofCheck`, on Windows, and the static box that takes a window as its label on Windows and Linux. Elsewhere they do nothing.
- wxOSX does not lay out right to left.

## What is missing

- A guide, and examples beyond the Hello sample.
- Disk images and notarization as part of a publish. The docs give the commands, and Velopack does both.
- Parts of wxWidgets, such as data view columns as objects, selecting several data view items at once, drag and drop, and the optional libraries.

The API will change before 1.0.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
