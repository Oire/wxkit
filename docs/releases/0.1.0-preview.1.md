The first preview of WxKit, .NET bindings to wxWidgets 3.3.4 that work with Native AOT. Install it with `dotnet add package WxKit --prerelease`.

## What works

- Windows on x64 and ARM64. A Native AOT publish links wxWidgets into the executable, so an application ships as one file of about 5 megabytes, and only links the classes it uses.
- 112 classes, generated from wxWidgets's headers: windows and the common controls, list, tree, and data view controls, toolbars, sizers, menus, the standard dialogs, drawing, images, validators, and the clipboard.
- Events as .NET events, async code that continues on the GUI thread, and exceptions in handlers that reach `Application.UnhandledException`.
- Members C# overrides: virtual lists, data view models of the application's own objects, validators, and `Accessible`, which describes a self-drawn control to screen readers.

## What is missing

- macOS and Linux, which come next after Windows.
- A guide. The README of the package and the doc comments, which come from wxWidgets's own, are what there is so far.
- Parts of wxWidgets, such as data view columns as objects, selecting several data view items at once, drag and drop, and the optional libraries, such as AUI, the styled text control, and the web view.

The API will change before 1.0, as the examples to come show what reads well and what does not.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
