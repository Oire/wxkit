The third preview of WxKit adds a getting started guide, two more samples, and most of the controls and dialogs an application reaches for. Install it with `dotnet add package WxKit --prerelease`.

## What is new

Guides and samples:

- A [getting started guide](https://github.com/trypsynth/wxkit/blob/master/docs/getting-started.md), which builds a small to-do list from an empty project to a published executable, with what makes it work with a screen reader along the way.
- A text editor sample, with standard menus, files opened and saved without blocking, find and replace, fonts, word wrap, the About box, and files dropped on it opening.
- A settings sample, with a dialog of pages, a form laid out with a grid bag sizer, pickers, a page that scrolls, and a validator.

Controls and dialogs:

- The color dialog, and the color, file, folder, and font pickers.
- The date and time pickers and the calendar, with dates as `DateTime?` in local time.
- `StaticBitmap`, bitmap buttons, command link buttons, and every book control: `Listbook`, `Choicebook`, `Treebook`, `Toolbook`, and `Simplebook`.
- `ScrolledWindow`, `InfoBar`, `ActivityIndicator`, `BitmapComboBox`, `BannerWindow`, `MiniFrame`, and the rearrange list, control, and dialog.
- `GridBagSizer`, which places items in cells, and `WrapSizer`, which wraps them onto more lines.
- The find and replace dialog, and the font dialog.
- `AboutBox.Show`, which shows the platform's About box.
- `NotificationMessage`, for notifications outside the application's windows, and `TaskBarIcon`, for an icon in the notification area, menu bar, or tray, with a menu.

Lists, trees, and data views:

- Images for trees, list views, and notebooks, given as any sequence of bitmaps.
- Any object kept with a list box, choice, combo box, tree, or data view tree item, which lives as long as the item does.
- Data view columns as `DataViewColumn` objects, and toolbar tools as `ToolBarTool` objects, which adding one now returns.
- Several items selected at once, in list boxes, trees, data views, and the multi-choice dialog, and a check list box's checked items.

Other changes:

- `StandardId` has every standard id wxWidgets has, generated from its headers.
- A text control checks spelling on macOS as well as Windows, with `EnableProofCheck`.
- A window that calls `DragAcceptFiles(true)` raises `DropFiles` with the paths of the files dropped on it.
- Members that fill a rectangle or a list, such as a list item's `GetItemRect` and a file dialog's `GetPaths`, take an `out` parameter.
- On Linux, a Native AOT application is smaller, since the linker now leaves out the parts of wxWidgets it does not use. The Hello sample went from 9.0 to 7.5 MB.

## Changes that may need code changes

Parameters that took a raw number now take an enum, and a few names read better:

- Style and flag parameters take enums, such as `Frame.CreateStatusBar`'s `StatusBarStyle`, `ShowFullScreen`'s `FullScreenStyle`, `Move` and `SetSize`'s `SizeFlags`, and `ProgressDialog`'s `ProgressDialogStyle`.
- `Window.ExtraStyle` is a `WindowExtraStyle` property you can set, rather than a getter and `SetExtraStyle`.
- `BoxSizer.Orientation` is an `Orientation`, rather than an `int`.
- The scroll events and event types are named with their words apart, such as `ScrollLineDown` rather than `ScrollLinedown`, and `EventType.Fullscreen` is `EventType.FullScreen`.
- Members that used to return nothing, such as a data view's `GetColumn` and a toolbar's `AddTool`, return the column or tool.
- `Frame.OnCreateStatusBar` and `OnCreateToolBar`, which a frame calls itself, are gone, as is the `GetImageList` of `DataViewTreeCtrl`, which returned nothing.

## Platform differences

- `Accessible` describes a self-drawn control through Microsoft Active Accessibility, so on Linux and macOS it does nothing yet, and their own accessibility describes the standard controls.
- Only the Windows list control can reorder its columns.
- On Linux, a data view column's width is the width it is shown at, which is 0 until the control is on screen.
- On macOS, a notification only shows from an app bundle.

## What is missing

- Printing, dragging data other than files, and the optional libraries, such as the grid, the styled text control, and HTML.
- Disk images and notarization as part of a publish. The docs give the commands, and Velopack does both.

The API will change before 1.0. The repository now keeps a snapshot of the public API, so a change shows up in review before it ships.

WxKit is heavily vibe coded. If AI-written code is a dealbreaker for you, this is not the project for you.
